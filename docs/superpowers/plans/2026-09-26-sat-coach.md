# SAT Coach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Subjects on student accounts, an SAT setup step, cross-sitting analytics, an exam-date planner, AI insights and a Digital SAT Tutor, and an SAT section in the Saturday parent email.

**Architecture:** Deterministic pure modules (analytics, planner, challenge builder, goals, LLM request/response core) carry the logic and are tested under Node; thin server modules load/store JSON in the private `portal-data` bucket and call them; route handlers and client components sit on top. AI only writes words and proposes actions the student confirms.

**Tech Stack:** Next.js 16 (App Router; `params` is a Promise — read `node_modules/next/dist/docs/` when unsure), TypeScript, zod, Supabase Storage via `readFreshJson`/`writeFreshJson`, Tailwind, lucide icons, Node test scripts (`node --no-warnings --experimental-strip-types scripts/test-*.mjs`), plain `fetch` to Groq/Gemini.

**Spec:** `docs/superpowers/specs/2026-09-26-sat-coach-design.md` (binding). The SAT Lab spec `docs/superpowers/specs/2026-09-22-sat-module-design.md` still binds.

## Global Constraints

- **Answer key:** analytics, insights and the tutor use only finished items (checked drill questions, submitted mock/practice modules); no `"use client"` module imports `bank.ts`, `serve.ts`, `session.ts`, `forms.ts`, `adaptive.ts`, `scoring.ts`, `drills.ts`, `store.ts` or any `src/lib/sat/*.json` — `npm run test:sat` enforces it (`scripts/check-sat-client-imports.mjs`); add every new server-only SAT module to that check's forbidden list.
- **Tutor pause:** tutor requests are refused, and cost nothing, while the student has an adaptive/practice sitting whose current module is running or on a break.
- **No invented scores:** only official practice ranges and labelled adaptive estimates are shown; mastery is a per-skill percentage, never a scaled score.
- **AI data minimisation:** prompts carry the first name, SAT profile and aggregated analytics only — never email, phone, guardians, school or photos.
- **Storage fails closed:** `readFreshJson`/`writeFreshJson` from `src/lib/exam-lab/storage-fresh.ts`; a failed read is never "no document" followed by a write.
- **Pakistan time:** plan dates are PKT calendar days `YYYY-MM-DD`; shown dates go through `formatPk` (`src/lib/portal/pk-time.ts`).
- **AI provider policy:** `scripts/check-ai-provider-policy.mjs` must pass — no Anthropic/OpenAI/Moonshot/Kimi packages, `api.openai.com`-style hosts or `process.env.OPENAI*`-style names. Groq is `https://api.groq.com/openai/v1/chat/completions`; Gemini is `generativelanguage.googleapis.com`.
- **Groq free tier:** 1,000 requests/day, 8,000 tokens/minute; keep each call's prompt under ~3,000 tokens; default model `qwen/qwen3.8-27b` (JSON mode + images), fallback `openai/gpt-oss-20b` (text only); Groq's firewall rejects Python urllib's default user agent — test with curl/fetch.
- **Module resolution:** inside `src/lib/sat/` (and `src/lib/sat/coach/`, `src/lib/ai/llm-core.ts`) sibling imports carry `.ts`, JSON imports carry `with { type: "json" }`, and modules Node tests import use no `@/` alias and no `server-only`.
- **UI:** portal tokens and idioms (`text-ice`, `text-fog`, `text-dust`, `text-cyan`, `bg-space/60`, `border-white/10`, `rounded-2xl`, `btn-primary`, `btn-ghost`, `font-display`, lucide icons); sparse pages; no horizontal overflow at 360 px (grid children `min-w-0`); no `window.confirm`/`alert`; plain-sentence errors (shared `invalidRequest` from `src/lib/sat/zod-messages.ts`).
- **Process:** never run `npm run build`/`next build` (a dev server runs from the main checkout); verify with `npx tsc --noEmit -p tsconfig.json`, `npm run test:sat`, `npm run test:portal`, `npm run test:access`, signed-out curls, `%TEMP%\next-dev.log`. `git add` explicit paths only (never `AGENTS.md`, `CLAUDE.md`, `mobile/`). Commits end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- **Skills normalisation:** the bank spells one skill two ways ("Cross-Text Connections" / "Cross-text Connections"); analytics key skills case-insensitively (`skill.toLowerCase()`), displaying the most common spelling.

    pacing: Record<"rw" | "math", { medianSec: number | null; targetSec: number; samples: number }>;
    pacingFlags: { skill: string; label: string; medianSec: number; accuracy: number }[];
    weakSkills: { key: string; label: string; domain: string; section: "rw" | "math"; mastery: number; priority: number }[];

    scores: { latestOfficial: SittingScore | null; latestEstimate: SittingScore | null; history: SittingScore[] };

- Rules (exact): weight w = 0.5^(ageDays/halfLife) (halfLife 14); mastery = (2 + Σw·correct) / (4 + Σw) (Beta(2,2) prior); confidence = Σw; trend = mastery over items in the last 14 days minus mastery over items 14–28 days ago (0 when either window is empty); skill key = `skill.toLowerCase()`, label = most frequent spelling; domain weights R&W `information-ideas` .26, `craft-structure` .28, `expression-ideas` .20, `standard-english` .26, Math `algebra` .35, `advanced-math` .35, `psda` .15, `geometry-trig` .15; priority = (1 − mastery) × domainWeight × min(1, confidence / 5); skills with attempts < 3 go to `notEnoughData`, the rest to `weakSkills` sorted by priority desc (top 5); pacing target R&W 71 s, Math 95 s; a pacing flag = skill with ≥5 timed attempts, median > 1.3 × target and mastery < 0.6; items with `domain`/`skill` null (practice tests) count for sections, difficulty (if known), pacing and totals only.
